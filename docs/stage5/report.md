# 阶段5：外部工具实施与有限验收

日期：2026-10-23。工程、自动化和本轮公开服务/浏览器链路已交付；复杂网页思考样本1条未通过来源支持核对，原结果保留。私有仓库功能已实现并进行模拟权限测试，真实私有仓库验收未运行（没有指定仓库和只读凭证）。本报告不把接口成功、小样本或AI评审视为普遍准确率保证。

## 实际交付

- 在原LangGraph单Agent中注册课程RAG、`web_search`、`read_web_page`、`github_list_directory`、`github_read_file`、`github_read_commit`。没有额外路由模型、聊天流程、多Agent或独立服务器。
- `ToolPolicy`固定本条请求的联网开关、公开搜索词及仓库授权ID；服务端执行前再次验证。严格课程请求强制关闭外部能力，缺证据不会自行联网。前端生成期间锁定选择，历史显示本条授权，切换账号/会话后外部选择默认关闭。
- 使用Tavily basic Search，关闭供应商答案生成和原始正文返回。用户在“公开搜索关键词”明确填写最多3组词，服务端仅允许原样调用这些词，不把教材、图片、私有仓库或完整历史拼入搜索。没有密钥时显示不可用并拒绝开启。服务端已读取用户自行填写的真实密钥，报告不含密钥。
- 网页搜索摘要仅为发现；独立读取实际正文才登记证据。`PublicHTTP`限制HTTP(S)和默认端口，校验全部DNS结果、连接已检查的数值地址、核验对端并按原域名验证TLS；每次重定向重新校验。阻止私网、回环、链路本地、云元数据、IPv4映射/转换IPv6等目标。不使用代理环境变量、Cookie或网页脚本。
- 公共连接有界尝试最多4个已检查地址，每个连接最多3秒；整个HTTP操作默认20秒，并受原360秒整轮截止和取消事件约束。默认最多3次跳转、网页1MiB/API 2MB响应、正文12000字符；明确返回空正文、类型不支持、截断及错误状态。不无限重试或抓取整站。
- 网页工具不能读取GitHub仓库域名及原始文件域名，跳转同样受限，避免绕过独立仓库授权。GitHub文档网站可作普通网页读取。
- 仓库授权属于当前账号及会话，创建时实际验证仓库与ref；每次分析将ref解析为SHA并固定后续读取。公共仓库匿名读取，私有Token仅从服务端“账号ID→准确仓库→Token”映射获取，无Token透传入口，不共享其他账号凭证。
- GitHub适配器仅构造固定REST GET路径；工具无写入、Shell或代码执行能力。通过Git Trees/Blobs按真实树条目读取，避免Contents API可能自动跟随符号链接；拒绝链接/子模块、二进制、超大文件及无效行区间。目录每页100项，提供下一offset；API树截断则明确失败。文本每次最多160行，引用绑定实际SHA、路径与有效行号。
- 增加独立`ExternalSource`，不会伪造课程Document/Chunk。来源由服务端登记统一编号，经权限、定位和AI支持核对后才公开；网页卡显示URL/访问时间，仓库卡显示固定提交/行号，课程引用兼容原接口。
- 去重使用规范化参数，语义相同的读取结果复用证据；搜索发现、目录、提交、正文的有效新信息均可计入进展，错误和重复结果不算进展。保留同轮多调用及真实tool_call_id协议。

## 持久化、历史与撤销

`0006_external`新增`messages.tool_policy`、`repository_grants`和`external_sources`，保持旧数据NULL、旧课程引用及v1私有协议兼容。新协议为v2，课程ID和外部ID分别保存；私有推理/完整工具协议继续只存服务端。

历史重放重新校验账号、会话、资料和仓库授权；当前未开启联网/未选择原仓库时，不带入其派生回答或协议。撤销授权或移除对应服务端私有凭证后，旧仓库回答和引用在读取接口中隐藏，原用户消息保留。保守策略也会隐藏同条混合回答中的其他内容，避免部分文本泄漏；原记录保存在服务端，重新授权产生新grant，不自动复活旧授权。

当前启用联网时，可以重新读取同对话最近20条已登记且仍获授权的历史网页地址；只是恢复允许读取的URL，正文必须本轮重新获取，不能复用旧编号。网页中实际解析出的有界链接也可继续读取；任意模型生成的URL被拒绝。

PostgreSQL保存消息、授权、最终来源及执行记录，历史刷新已有真实验证。没有新增进程崩溃后的中途续跑；沿用原pending中断恢复，用户新发一轮重新执行。没有创建LangGraph检查点或宣称进程恢复可继续未结束请求。

最终入库时重新锁定/核验仓库授权与pending状态，取消、撤销及迟到结果不能覆盖已终止状态。删除消息清理所属外部来源和私有协议；删除会话同时清理仓库授权。普通日志及前端执行记录不含凭证、正文工具参数或内部推理。

## 配置和使用

根目录`.env`已加入以下字段，已有模型和数据库配置保留：

```dotenv
WEB_SEARCH_PROVIDER=tavily
TAVILY_API_KEY=
EXTERNAL_TIMEOUT=20
GITHUB_CREDENTIALS={}
```

真实密钥由用户填写，不能放进前端变量或`.env.example`。修改配置后重启API。启动顺序沿用README：PostgreSQL/Redis → `alembic upgrade head` → API/Celery → 前端。本轮主库已由0005升级0006，没有重建任何旧资料或索引，生产仍为dense/512维。

聊天使用：勾选联网并填写公开关键词；仓库输入`owner/repo`与可选ref，点击验证授权，再勾选供本条使用。两者互相独立。严格课程范围覆盖这些选择。刷新后必须重新选择本条外部权限，历史已登记来源仍可查看（仓库授权失效时隐藏）。

私有仓库由管理员将`GITHUB_CREDENTIALS`设为JSON对象，例如`{"账号UUID":{"owner/repo":"只读Token"}}`，键中的仓库名使用小写。Token只授指定仓库的Contents只读权限及必要Metadata读取，不授写入；账号UUID来自`GET /api/v1/me`。配置凭证仅代表服务端具备访问能力，用户仍须创建会话授权并在发送时选择。应用不依赖Codex会话的搜索/GitHub插件。实际Token权限需由管理员在GitHub侧限制，不能仅凭GET适配器宣称Token本身没有其他权限。

## 真实结果与原失败

冻结样本与预期（本机原始材料，未随公开仓库发布）后首次运行6题：直接回答、严格课程、普通网页、思考网页、仓库、仓库+课程。首轮4/6形成通过检查的完整回答；普通网页遇到连接超时，思考网页未通过引用支持核对。原始答案、评分及候选回答诊断（本机原始材料，未随公开仓库发布）保留。

修复连接尝试和真实网页链接后，原题重跑属于回归，不称新保留集。结果5/6：普通网页完成搜索、读取和引用；复杂思考网页尝试读取更多子页时仍遇网络失败，候选回答未通过AI支持核对，公开结果是限制说明，没有强行放行。其余直接、RAG、仓库和组合路径通过。6条本机完成耗时约2.0～34.2秒，仅为本次运行，包含失败，不是生产性能承诺。

开放回答由配置模型辅助评分，Codex核对原结果及程序检查，均属AI辅助、非独立人工评审；同模型相关偏差和引用核对误判仍可能存在。只读到了README的Hello World不能声称仓库实现复杂算法。此次以小型公共示例验证跨工具路径，不代表大型代码库分析质量。未将输出长度作为质量评分，未汇总全部探针/浏览器/转写的币种账单。

浏览器首轮发现刷新后重新读取被`url_not_discovered`拒绝，进而触发历史编号失效；失败记录（本机原始材料，未随公开仓库发布）保留。修复仅恢复已授权历史URL、重新读取正文后，完整流程通过。图片回归脚本首轮遗漏保存接口的JSON body导致422，原运行目录保留，补齐参数后4项通过。

测试环境原`.pytest_tmp`无访问权限，改用独立临时目录；首次将目录放在`.eval-cache`触发了旧评测缓存路径测试的合理断言，保留该次结果（本机原始材料，未随公开仓库发布），移至独立测试目录后全套通过。根目录格式扫描遇到两个无权访问的旧缓存目录，最终对全部105个`app/tests/scripts/alembic`源文件检查通过。uv默认全局缓存无权访问，使用工作区独立缓存后锁文件检查通过。未修改旧检索行为以迎合测试。

迁移开发脚本首次将JSON常量嵌入SQL，被SQLAlchemy当作绑定参数而失败；改为显式绑定JSON后通过。首轮临时库也已在finally清理，不涉及主库降级。测试夹具增补时的缺失导入已修正，原测试输出保留在执行记录中。

最终两轮共4个隔离账号及11类关联数据已清理，残留均为0，见首轮清理（本机原始材料，未随公开仓库发布）、回归轮清理（本机原始材料，未随公开仓库发布）。主API已加载最终代码，前端和Celery运行，健康及生产检索配置见runtime.json（本机原始材料，未随公开仓库发布）。

## 复现

在backend执行：

```powershell
uv run --no-sync alembic upgrade head
uv run --no-sync python -m scripts.probe_stage5
uv run --no-sync python -m scripts.check_stage5_migration
uv run --no-sync python -m scripts.accept_stage5
```

真实验收使用已配置服务，会产生服务用量；只使用隔离账号和公开/自制数据，每次新建运行目录。已经看过的样本重跑使用`--kind regression`。程序会输出忽略目录中的context路径，浏览器验证前设置`STAGE5_CONTEXT`为该文件，然后在frontend执行：

```powershell
npx playwright test e2e/stage5.spec.ts
```

浏览器完整测试会撤销其测试仓库授权；同一context不应重复当作全新验收。结束后在backend运行`python -m scripts.accept_stage5 --cleanup <context.json>`，按本轮账号ID清理，报告保留。图片回归为`python -m scripts.regress_stage5_images <context.json>`。

## 保留边界

没有切换模型、生产检索策略、Embedding或向量库；没有自动重建资料。没有加入反馈、配额、费用界面、独立设置页、OAuth平台、部署体系或仓库写操作。Python无法强杀同步HTTP线程，但等待可取消，迟到HTTP线程不接触数据库或执行工具，仍受有限网络时限和原16槽约束。私有凭证本轮未配置，真实私有验收仍是明确待办。
