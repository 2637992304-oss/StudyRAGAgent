日期：2026-10-22。状态：工程与必需功能、真实协议及浏览器验收完成；普通模式1道模型质量失败保留。原阶段4报告 `docs/stage4/report.md` 保留，本报告不沿用原117项结果作为增补完成证据。

## 实际实现

- 聊天输入区提供两状态“深度思考”按钮，首次关闭，开启后蓝色高亮，原生键盘操作及 `aria-pressed`。提示固定为“适合复杂推导、错题分析和多步问题，回答可能需要更长时间。”
- 偏好仅存当前浏览器的 `studyrag-thinking:<account_id>`，账号隔离，刷新恢复，不跨设备同步；存储不可用时仍能发送。生成时锁定选择，每条用户消息与对应回答记录发送快照，旧消息NULL显示“思考模式未记录（旧版本）”。
- 消息请求的 `thinking` 使用StrictBool，缺省为false，字符串/数字/null不转换成开启；客户端提交用途、上限等额外字段不参与用途选择。
- `CallOptions` 为不可变配置，`Execution` 为请求独立的单调时钟截止与取消信号。每轮所有Agent模型回合使用同一配置，不修改全局Settings或环境变量。
- `0005_thinking` 仅增加可空 `thinking`、`call_config`、`protocol_state`、`reply_to_id`。不回填旧消息，保留旧消息与附件；请求与回答通过reply_to_id关联。配置快照及私有协议不返回前端。

| Agent关闭 | disabled | 不传 | 2048 | 90秒 |

上述试运行初值本次未调整。课程检索独立45秒；整轮360秒；连接10秒、无数据读取30秒，各步骤实际时限受剩余整轮时间约束。开启模式不发送不适用的temperature。旧脚本省略请求级参数时保留原LLM_*调用兼容，生产聊天、转写和引用核对均显式选用途。

“看图片解题”属于Agent解答，跟随按钮；Celery的图片转写固定关闭。两种模式均经过现有严格范围、来源关联与AI支持核对；没有有效资料不得冒充课程结论。只注册原有 `search_course_materials`，没有Web Search/GitHub工具、路由模型或多Agent。

## 协议状态、上下文和删除

按2026-10-22核对的[DeepSeek思考模式协议](https://api-docs.deepseek.com/guides/thinking_mode/)与[工具调用协议](https://api-docs.deepseek.com/guides/tool_calls/)，带tools的请求应回传先前真实返回的reasoning_content；Chat Completions不能随意伪造中间工具调用。

实际保存每轮供应商返回的assistant/tool完整消息、真实调用ID和必要reasoning_content，仅在服务端消息私有JSON内；不持久化重复图片base64，不向普通日志或验收报告导出内部推理。工具结果回传和多轮恢复使用真实协议，未补造空推理字段。

重新加载时，同时读取账号/会话/资源范围下的原用户消息与授权图片，并核验私有工具来源是否仍有效。历史工具编号只能作为历史，当前引用必须重新获得本轮证据。有界窗口仍采用12条消息/18000字符、图片8张/24MiB。私有协议只整段重放，不截成半段工具消息。

旧消息没有协议、原提问已删除、来源失效、回答被支持核对拒绝或完整协议超出上下文预算时，保留已展示回答和可访问图片作为明确标注的历史参考数据，重新进行本轮决策/检索；不伪造assistant/tool协议，也不默默丢失已展示学习内容。超出原历史窗口的内容不能保证继续记忆。删消息会删除该消息内协议，删会话会级联删除；附件生命周期及保存入库关系沿用阶段4。旧会话、刷新和开关跨消息切换均有真实验证。

## 超时、停止和一致性

- 完整聚合一轮文字、推理和全部工具参数并校验后才执行工具；只有检查后的最终文字通过原SSE事件发送，内部推理与参数不展示。
- 同步模型接收放入有界守护线程，调用方以可取消的短等待检查步骤及整轮截止。因此完全无流量时也可终止，不依赖下一个SSE片段。重试/503退避也占本次步骤与整轮时间，无降级关闭思考。
- 取消端点 `POST /chat/sessions/{id}/cancel` 校验归属并持久化终止；本进程事件立即通知等待，跨Worker通过有界数据库探测同步。断开浏览器也会触发请求级取消。最终落库前锁定并重新检查pending，迟到结果不能覆盖已终止消息。
- PostgreSQL检索使用独立会话和不超过剩余时间的statement_timeout；主聊天事务语句最长10秒，连接/连接池等待也有上限。取消状态探测有200ms前台等待上限和2个后台槽，数据库探测本身不能阻塞前台流。
- 区分 `truncated`、`connect_timeout`、`read_timeout`、`step_timeout`、`deadline_exceeded`、`cancelled` 及原供应商HTTP错误码。截断/错误不作为完成答案落库。pending恢复至少900秒，并考虑已保存整轮截止加60秒，避免误杀合法长请求。
- Python不能强杀正在执行的同步HTTP或本地Embedding线程。前台放弃后HTTP线程只做请求/解析，受有限连接/读取时限及16槽限制，不执行工具或写数据库；迟到检索只读且拥有独立会话。远端是否立即停止计费不作保证。数据库彻底不可用或进程被强杀时，落库本身仍依赖恢复，使用既有pending恢复机制。

## 原失败和修复

1. 专项测试首次16通过/8个夹具导入错误，补齐fixture导入后专项通过；不称为产品质量失败。
2. 首轮真实图片资料问题误走“缺聊天附件”澄清；补充已存图片资料应先检索转写的系统规则。
3. 首轮无文字意图/无历史任务约定时直接执行图中文字任务；补充必须先确认用户意图，避免图片命令代替用户请求。两处使用原规则要求修复，未改成强制学习模式。
4. 首次浏览器断言只看active类，截图发现全局按钮选择器盖住颜色。修复CSS优先级，并增加真实计算样式断言；旧截图保留，最终截图另存。
5. 最终普通模式组合题35错误，属于模型质量限制，保留原文及评分，不追加针对该题的提示优化或修改参考。

## 运行与复现

正常运行继续使用README的后端、Celery和前端命令，先运行 `alembic upgrade head`，原 `.env` 不需新增字段即可采用本次默认值；可选变量见根目录 `.env.example`。前端 `npm ci` 包含Playwright开发依赖；浏览器验收使用本机Chrome。

在backend运行：

```text
python -m scripts.probe_thinking
python -m scripts.check_thinking_migration
python -m scripts.observe_thinking_service --service api --audit ../docs/stage4_thinking/api_wire.jsonl
python -m scripts.observe_thinking_service --service worker --audit ../docs/stage4_thinking/worker_wire.jsonl
python -m scripts.accept_thinking --fixtures ../docs/stage4_thinking/fixtures_final
python -m scripts.summarize_thinking ../docs/stage4_thinking/runs/<run>/results.json
```

两个observe服务命令分别在独立终端运行，仅为验收参数观察入口。正式运行无需启用观察器。已有冻结文件不要重复构建，构建脚本会拒绝覆盖。每次真实验收新建运行目录和隔离账号，结果不会覆盖旧运行。

浏览器前设置 `THINKING_CONTEXT` 为脚本输出的 `.eval-cache/thinking/<run>.json`，在frontend运行 `npx playwright test`。context只含本次隔离资源ID/账号信息；测试密码固定仅供临时验收，不能用于正常账号。完成浏览器测试后在backend运行 `python -m scripts.accept_thinking --cleanup <context.json>`，按本次账号ID清理所有测试资源并保留文档证据。

验收参数观察服务已关闭，API/Worker已按普通方式加载最终代码；运行状态（本机原始材料，未随公开仓库发布）确认健康接口正常、dense/512维保持不变。
