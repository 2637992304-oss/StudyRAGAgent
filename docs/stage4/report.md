# 阶段 4：实施与验收报告

状态：2026-10-21，工程实现及本轮有限样本验收完成。未要求用户人工审核；本报告中的开放性答案评审均为 AI 辅助评审，不代表独立真人验收或全部教材的准确率保证。

## 实际交付

- LangGraph 单 Agent：直接回答、课程检索、澄清和说明限制；仅注册 `search_course_materials`，没有 Web Search / GitHub 调用。模型完整结束工具参数后才执行；同轮多调用按序处理，重复、未知工具和越权参数被拒绝。
- DeepSeek Flash 图文与流式工具适配器：完整结束标记、调用 ID 和参数聚合，思考内容仅用于供应商要求的内存协议回传，不进入回答或普通日志。
- JPEG / PNG / WebP 两个入口：聊天附件上传、粘贴、预览、移除、刷新恢复；资料图片经 Celery 真实转写、切块和既有 512 维 Embedding 入库。聊天图片只在明确保存后复制为课程资料；两份原文件独立，删除互不误伤。
- 多轮问题实际带入有界历史及图片；用户可自然语言要求讲题、分析作答或先给提示，无强制学习模式。没有课程证据不再全局拒答；严格课程请求仍受证据约束。
- 来源先核验账号、课程、资料状态及编号，再对被引用结论进行一次有界 AI 支持检查；不支持的内容整段降级说明，避免只去掉引用保留断言。检查后再次确认来源仍有效。
- Markdown 与 KaTeX 数学公式，跳过原始 HTML，模型输出的远程图片不加载；引用识别跳过代码及数学块，避免把列表索引误当成来源。图片来源在页面内查看，旧文档预览方式保留。
- `0004_stage4`：新增 attachments 及消息的 agent_trace、stop_reason、answer_scope。旧资料和消息兼容，不创建占位向量、不自动重建或切换索引。
- 中断时失败落库；进程被杀导致的旧 pending 在下一次请求时按配置计算的失效期限恢复（至少15分钟，默认21分钟）。模型轮数、单次调用超时、重复查询及无新增证据检测只用于正常终止，不建设反馈、配额或费用管理模块。

## 运行与复现

按根目录 README 启动 PostgreSQL / Redis，然后在 `backend/`：

```powershell
uv sync --extra dev --frozen
uv run --no-sync alembic upgrade head
uv run --no-sync uvicorn app.main:app --host 127.0.0.1 --port 8000
```

另开终端启动 Worker：

```powershell
uv run --no-sync celery -A app.workers.tasks:celery_app worker --loglevel=warning --pool=solo
```

`frontend/` 执行 `npm ci`、`npm run dev`。模型继续使用服务端已有 DeepSeek Flash 配置，不打印或复制密钥，不需要增加新的供应商密钥。

隔离验收命令（真实调用会产生供应商用量）：

```powershell
uv run --no-sync python -m scripts.build_stage4_fixtures
uv run --no-sync python -m scripts.probe_stage4
uv run --no-sync python -m scripts.smoke_stage4
```

脚本为每次真实验收新建账号与课程，并创建独立运行目录；`backend/.eval-cache/stage4/<run>.json` 保存本次资源ID。浏览器验证后运行 `python -m scripts.smoke_stage4 --cleanup <context.json>`，仅清理对应隔离资源，报告保留。本次两组隔离账号（包含首轮邮箱大小写失败遗留）已在浏览器验收后清理，不涉及原有账号资料。原始失败过程与截图保留。开发探针可重跑；已经看过的固定样本重跑只能称回归，不再称新保留集。

## 新增接口与生命周期

- `POST/GET /api/v1/chat/sessions/{id}/attachments`：上传/列出当前会话图片，包括未发送草稿。
- `GET /api/v1/chat/attachments/{id}/file`、`DELETE /api/v1/chat/attachments/{id}`：私有读取/移除；生成过程中不允许移除。
- `POST /api/v1/chat/attachments/{id}/save`：明确保存到当前课程，复制文件，幂等返回已保存资料；处理失败沿用资料重试接口。
- `POST .../messages`：兼容content，增加attachment_ids；仅图片可发送，API可显式传answer_scope=auto/strict。自然语言识别严格范围并保留到追问，明确允许通用知识可切回。
- `DELETE /api/v1/chat/sessions/{sid}/messages/{mid}`：删除该消息及所属聊天附件，不删除已保存的课程副本。
- `DELETE /api/v1/chat/sessions/{sid}`：清理整个对话、引用和聊天附件；保留课程副本。
- 未发送草稿刷新后仍保留，可明确移除或随会话删除；没有擅自增加定期清理用户图片的任务。

## 实现选择与限制

- 最终答案先缓冲，再检查引用，最后通过兼容的SSE增量发送；工具进度可先到达。当前不是模型逐token直接显示，严谨检查会增加首段等待。
- 引用ID/权限/定位检查是程序核验；内容支持关系由同一配置模型进行AI核对，仍可能判断错误，不是形式化事实证明。严格范围有基础自然语言识别和明确API字段，复杂否定表达仍需更广测试。
- 检索工具使用独立只读会话，有界等待；PostgreSQL设置语句超时。超时后不使用迟到结果，底层本地Embedding线程可能稍后结束，不能视为强制杀掉所有CPU工作。
- 历史最多12条、18000字符、8张图片，图片原始总量24MiB，单条最多4图；这是协议兼容与上下文边界，超出的旧图明确提示未带入。最大2000万像素且只接受静态图片；GIF/动画和音视频未纳入。
- 图片描述接入文字检索，可能遗漏视觉细节；不是完整视觉向量检索，也未将旧PDF改为逐页视觉识别。
- 旧阶段3的广课程、生产推广、可回退副本索引及容量验证仍是独立后续事项，本轮没有重建私人PDF或开展新一轮检索调参。
- 阶段5仅需沿用图的工具节点注册获授权的Web Search / GitHub只读工具；本轮没有外部搜索或仓库操作能力。
