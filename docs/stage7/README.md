# 阶段7：对话式偏好与当前会话摘要

2026-11-04 新版入口：[自由文本契约](free-text-design.md)、[进度](free-text-progress.md)、[验收与采用](free-text-report.md)。text 模式取消四字段限制；下文四字段、旧接口和旧迁移说明仅适用于 legacy 兼容模式及历史试点，不能作为新版实施要求。新版 0012～0015 尚未在业务库执行。

该功能复用单LangGraph Agent、PostgreSQL和现有Celery/Redis。源码及示例配置默认关闭；本机业务实例已于2026-11-03完成受控迁移并开启有限试点，实际状态见[最新报告](report.md)。其他环境仍须独立完成迁移与启用，不能用源码默认值推断本机当前状态。

## 用户交互

- 明确说“以后这门课用Python举例”，Agent可调用受限记忆工具；成功提交后显示回执及撤销。临时要求不应保存。默认当前课程，明确“所有课程”才使用全局范围。
- 当前会话至少3个独立用户回合出现一致信号时，可在回答下方提出建议。用户确认前不生效；支持编辑、保存、不再建议和仅关闭本次卡片。建议7天到期，重复/失效卡片不能覆盖新设置。
- 明确接受建议的自然表达（如“这个建议不错，就帮我记住吧”）只确认当前会话唯一匹配候选；否定、引述、假设或歧义时使用卡片。保存、确认、刷新和工具历史重放不得重复执行副作用。
- 记忆管理使用聊天顶部的弹窗入口，支持查看有效偏好、编辑、删除、启停读写和建议，以及恢复被抑制的建议类型，不需要独立设置页面。
- 摘要按会话开启，Celery后台自动维护。查看覆盖消息数、更新时间及任务状态；可清除并关闭或重建。摘要仅供当前会话参考，不是课程事实证据，也不能保证逐字保留全部历史。

偏好字段：讲解语言（中文/英文）、代码语言、解释详细程度、先给提示。系统权限和核验规则优先，其次本轮要求、课程偏好、全局偏好。记忆不能授予联网或仓库权限。纯记忆请求由服务器生成操作回执，混合课程问题仍按原流程核验后发布。

## 配置、迁移与回退

`MEMORY_PREFERENCES_ENABLED`、`MEMORY_SUGGESTIONS_ENABLED`、`MEMORY_SUMMARY_ENABLED`独立控制，建议依赖偏好功能。摘要另有批次、字符、超时、队列和依赖校验分批大小，见`.env.example`。预算/收尾候选的原默认不改变。

新增正式迁移`0010_memory`及`0011_memory_dependencies`，五张记忆表加一张摘要来源依赖表，不改写旧消息或资料，不自动回填旧摘要。业务库更新需另行授权，先核对原库/资料目录及实际head、备份并验证恢复。不能在业务库直接运行验证脚本或降级。

关闭开关可回退行为并保留数据；已有记忆仍可查看、删除、撤销。降级到0009会删除记忆表及其中数据，旧消息保留；这不是日常功能回退方式。

聊天来源删除会使相关偏好/建议失效；手动在管理入口保存形成独立设置。摘要保留完整传递依赖，并在读取和发布前复查。来源变更只失效依赖它的摘要（包含传递来源），不再让同账号无关会话全部失效；清除后旧任务不能复活内容。来源依赖独立持久化，原300条限制改为分批校验大小，不限制总覆盖条数；按完整回合自适应缩小摘要输入，并通过持久任务连续推进。助手正文不作为用户意图摘入摘要，但仍保留完整来源指纹。单轮用户原文自身超出输入预算时明确显示暂停原因，保留原文。

## 接口与复现

- `/api/v1/memory/preferences`：GET/PUT；DELETE携带版本；`/memory/settings`：PATCH。
- `/memory/suggestions/{id}/accept`、`dismiss`和`/memory/operations/{id}/undo`：POST，带版本和适用的幂等键。
- `/chat/sessions/{id}/memory`：GET/PATCH/DELETE；`.../regenerate`：POST；`.../memory/suggestions`：GET。
- SSE新增可选`memory_operation`与`memory_suggestion`事件；历史消息可选`memory`字段恢复状态，旧客户端可忽略。saved仅在提交后发出；同轮多字段写入整批原子提交，校验或提交失败不留下其中一部分。

隔离工程验证：在backend中运行已有虚拟环境的`python -m scripts.validate_memory_services`。`--full`先执行全后端回归；创建带随机身份的专用PG/Redis，执行迁移、专项、真实Celery进程中断恢复及实际HTTP/浏览器验证，最后只清理自己的容器。需要Docker、现有Node依赖和Chrome。验证替身不会产生真实模型费用。

`--real`额外运行冻结的16情境×3配置对照，使用必要的本机模型配置，但保留隔离数据库与文件路径；必须先授权费用。真实HTTP尝试累计记入`.runtime/stage7/real-request-budget.json`，上限240，重跑共享旧额度，不得删账本重置。原始自制问答和失败留在本机`.runtime/stage7/`，不发布私人协议或凭证。

修复回归入口：`python -m scripts.validate_memory_services --full --budget --real --repair`。`--repair`将原16题作为回归集，并在调用前冻结8个新情境，运行B/C两种启用配置；所有尝试沿用同一240次持久额度。摘要任务调用前持久记录尝试，取消后仍补记已知用量；进程强杀留下未知用量，不能当作零。旧首轮未导出的两次摘要用量仍无法恢复。

主动建议除主Agent自行调用工具外，新增同一图内的有界检查：每第三个用户回合、至少3条近期用户原文、无pending卡/暂存操作且开关及原轮数/时间预算允许时才调用。该步骤仅可提出建议或SKIP，不能保存；使用独立memory_suggestion用途计量，不新增Agent、不提高原限制。明确保存仍由主Agent语义识别；服务端对目标字段补原文依据校验，模糊指代可要求澄清，不用知识掌握陈述推断讲解风格。

后续修复最终回归使用`--real --repair-final`：B配置包含原16题和8个已观察情境作为回归，以及两个最终冻结新情境；C配置补两个长对话情境，共28项，不是完整三配置矩阵。按本次用户追加授权，累计上限调整至320、原已用次数保留，使用`--extended-budget`对应此账本；参数本身不构成调用授权，其他任务须另行确认其额度。历史失败轮及首次两次摘要用量缺口继续保留。

明确唯一候选确认的完整短句可在同一图直接进入受限确认工具；来源、归属、版本、有效期和开关仍重新检查。混合问题不走此快捷路径，多个候选不能靠模型自选ID确认。正常澄清回答可附待确认建议，仍不保存有效偏好；失败或取消不提交。代码语言的唯一字面目标或明确“从X改成Y”关系由服务端绑定，防止模型反向选择旧值；无法唯一确定时澄清。整批冲突回执持久保存，刷新后仍显示“整批未保存”，不提供撤销。
