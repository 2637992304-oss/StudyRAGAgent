# 自由文本长期记忆：实施契约

2026-11-04。此文是新版执行入口；四字段仅属于兼容的 legacy 模式。保留单 LangGraph Agent、FastAPI、PostgreSQL/pgvector、Celery/Redis 与 React，不接入 Mem0。工程证据和采用限制见 [验收记录](free-text-report.md)。本次不包含业务迁移、配置切换或部署。

## 正文与写入意图

- 不设置内容类别白名单，可保存偏好、背景、目标和用户指定的备忘。自由文本是数据，不能覆盖系统规则、授予工具权限或充当课程检索证据。
- 聊天中明确要求长期保存，由同一个 Agent 提取正文并调用受限工具。提取保留条件、否定、例外、日期和数值，排除顺带提出的当轮问题。不能只靠关键词授权写入。
- 管理入口新增或编辑按用户原文保存，包括空格与换行；不自动扩写、压缩或截断。推断内容只生成当前聊天的待确认卡片，至少三个独立用户回合、有界完整原文作为证据，确认前不入有效记忆。
- `content` 使用 Text，应用默认最多 1000 个 Unicode 码点（Python len、前端 Array.from），由 `MEMORY_CONTENT_MAX_CHARS` 配置；不是 UTF-16 长度，也不是 Token 预算。拒绝全空白与孤立代理字符。
- 原文长但长期信息少时只提取相关信息。多个独立要求可分别保存，整轮原子提交；不可拆散条件与例外。单条仍超长时先 `organize_memory` 形成最多八条候选，经用户确认后保存。管理入口保留超长输入、阻止直接保存，提供“帮助整理为多条”，整理 API 输入上限 12000 码点。
- 整理不能无损完成时应失败或请求分段，不静默截断。长篇教材和代码使用资料系统。实际入模预算另行核算；不能声称处理了预算外内容。

## 模型与事务

六张新表：`memory_items`、`memory_item_revisions`、`memory_item_sources`、`memory_item_relations`、`memory_item_embeddings`、`memory_index_jobs`。复用 `MemoryOperation`、`MemorySuggestion`，新增 `schema_version=2`。

条目字段包含稳定 ID、认证绑定 owner、原文 content、global/course 范围、active/superseded/deleted/invalidated 状态、递增 version、explicit_request/user_confirmed/manual 写入依据、可选 applies_when/exceptions/tags、always/relevant 使用方式、valid_from/expires_at 和服务器时间。条件/例外各最多 300 字符，最多十个 32 字符标签；不是新的业务类别。

版本快照、来源指纹、关系、操作前后状态与索引 outbox 同事务写入。手动编辑形成独立用户设置；聊天更新继承旧版本必要来源。账号锁、版本校验和请求指纹防止并发覆盖、相同幂等键换内容、重放重复写入。一个回答涉及的暂存写入整批提交，任一冲突整批回滚并持久化失败回执；取消、失败、无证据回答不暗中提交。撤销只操作该操作涉及的条目，后续版本变化时拒绝，不恢复账号快照。

## Agent、范围与冲突

工具：find_memories、save_memory、update_memory、delete_memory、propose_memory、confirm_memory、organize_memory。工具 staged 不表示成功；最终数据库提交后发送回执。纯管理请求使用服务端操作结果；混合课程问题保持来源核验、最多一次修复与复核、核验后发布。

默认当前课程。明确全局/所有课程才可写全局；模型认为“有普遍价值”不构成扩大范围的依据。服务端保守检查全局表达；新建时没有明确全局表达则按既定规则落到当前课程，工具和回执返回实际范围。罕见全局表达可通过管理入口选择范围；该检查不决定是否授权保存正文。用户本轮要求高于长期偏好，课程具体要求高于全局一般要求。语义重复、替代、细化、共存由 Agent 判断，服务器校验范围、目标版本和事务；不以向量相似度或时间新旧直接覆盖。

同范围“简短→详细”更新同 ID；“这次详细”不修改记忆；“数学推导详细，其他简短”保留条件；课程例外保留全局设置。多条合并记录 supersedes 关系。歧义需要澄清。手动新增自由文本不执行额外模型语义合并，用户可能保留相互矛盾的独立正文；此时应编辑整理，不能宣称数据库已经消除所有语义冲突。

建议包含候选、真实证据、范围、目标版本、epoch、到期和状态；现有有界检查节奏、去重和七天到期规则保留。同回答最多一张卡；确认时重查开关、来源、版本及期限。唯一候选的明确短确认可在聊天完成，其他情形使用卡片。编辑后保存编辑结果。有替代目标的候选被编辑后，额外展示原条目及版本，用户必须明确勾选确认替换；模型复查不能代替这次用户操作。其余编辑候选有界调用现有模型复查冲突，冲突/不确定时保持待确认，不自动选择新覆盖目标；调用和未知usage持久计量。拒绝类似内容按账号和范围抑制，可恢复；当前近似抑制使用文本相似度及 Agent 提示，不能保证任意语义改写均被识别。

## 读取、失效、异步

always 持续参考与 relevant 相关召回分开，独立字符容量默认 6000，仍纳入实际 Token 预算和核验快照。账号、课程、来源、有效期、状态过滤；持续要求超容量时明确报错，不能悄悄丢弃。每范围最多扫描 500 条活动候选，超出时明确提示整理；管理入口保留搜索与容量提示。

relevant 复用现有本地 512 维 Embedding、独立 pgvector 表及有界文本回退，最多八条。向量绑定条目版本、正文哈希及模型标识；旧向量、迟到结果不覆盖新版本。保存不依赖索引成功。outbox 持久调度、账号/任务锁、租约、执行 token、最多两次尝试、真实进程中断后恢复；重复投递不重复发布。

来源绑定具体修订，包括消息、会话范围/策略、附件、读取过的资料片段/文档、仓库授权及回执消息；删除、失败、改动、撤权后复查失效。带资料或附件依赖的记忆继续受当前课程/选中资料/会话权限约束。该保守策略可能让普通偏好随所在消息的附件或授权一起失效；可由用户在管理入口明确重新保存为独立设置。

摘要保留现有按会话开启的后台链路；不替代原文和课程证据，不反向恢复删除的长期要求。新回答在私有协议快照记录使用过的记忆 ID/版本，摘要依赖跟踪这些版本；修改后摘要失效。重建从用户原文推进，助手正文不进入摘要输入；失效旧回答的记忆版本不重新加入重建依赖，避免永久卡住；有效版本继续约束现有摘要。基于其他记忆产生的新记忆也绑定父版本；父版本改变、删除或来源失效后递归失效，循环依赖拒绝使用。历史完整工具协议仅在来源及记忆版本仍有效时重放，否则旧正文和旧工具结果不参与当前上下文。旧版历史没有此依赖信息，不能追溯证明每条旧回答使用了什么记忆。

## 接口、前端、兼容

`/api/v1/memory/capabilities` 返回引擎、协议和长度限制。`/items` GET/POST、`/items/{id}` GET/PUT/DELETE、`/items-batch`、`/organize`、`/text-suggestions/{id}/accept|dismiss`、`/text-operations/{id}/undo`、`/text-suppressions`；写入携带版本和幂等键。共享原 settings/会话摘要接口。

SSE `memory_item_operation`、`memory_item_suggestion` 与历史 schema2 元数据恢复实际状态。前端管理弹窗移除类型下拉，提供正文、搜索、范围、使用方式、日期、编辑/删除、来源及版本历史。聊天回执支持撤销，建议卡支持编辑确认/抑制，刷新与切换从服务端恢复；不凭按钮点击假定已保存。保留 legacy 渲染及普通聊天兼容；旧版写入入口在 text/off 返回明确拒绝。

## 迁移与采用

新增 0012～0015：六表、确定性旧值转换、PG 约束、旧卡片投影。保留旧 ID、版本、范围、删除/失效状态和来源，转换不调用模型；不改已使用的 0010/0011。旧卡片保留 legacy_payload；旧操作通过适配器撤销，缺少历史来源指纹的旧聊天操作安全拒绝撤销，需用户手动重新保存。

`MEMORY_ENGINE=legacy|text|off`，公共默认 legacy，三项能力仍默认 false。同实例只使用一个长期记忆引擎，不双写。启用 text 前须在已授权维护窗口完成备份、恢复演练、迁移和停止旧写入后的增量核对；复制后旧写入发生变化会拒绝切换。首次 text 写入留下持久标记，不能回退到陈旧 legacy 数据；故障使用 off，保留条目以便管理。数据库降级删表不作为行为回退。

新模式工程通过与真实语义通过分别判定；当前采用结论以验收记录为准。本次未授权业务模式切换或默认推广。
